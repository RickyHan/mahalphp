# mahalphp — 민원 자동처리 시스템

- 웹: **민원 자동처리 시스템** (`/admin`)
- 앱: **민원 카카오톡 메시지 자동 수집** (Android)

Android 휴대폰에 오는 **카카오톡 알림**을 수집해 서버(MySQL)에 저장하고, **웹 관리 화면**에서 대화·사진·민원·통계·참여자 이력을 봅니다. 민원 분류(Google Gemini)를 비롯한 **모든 처리는 서버가 하고, 앱은 수집만** 합니다.

```
[휴대폰: 민원 카톡 수집 앱]                  [Ubuntu 서버: kakao-collector 서비스]            [MySQL]
 카톡 알림 수신 ──────── POST /api/messages ──▶  저장 · 참여자 이력 기록                 ─▶ kakao_collector
 (누가·어느 방·내용·사진)                       백그라운드 워커: Gemini 민원 분류·묶음
 '민원 접수 안내' 카톡 답장 ◀─ GET /api/replies ─  새 민원 → 접수 안내 대기열
                                                웹 관리 화면 /admin (대화·사진·검색·민원·통계·이력·설정)
```

| 경로 | 내용 |
|---|---|
| `deploy/install.sh` | Ubuntu 서버 원클릭 설치 (MySQL·서비스 등록 포함) |
| `server/` | 서버 (Python 3.10+, FastAPI, PyMySQL) — API · 웹 · 민원 분류 워커 |
| `server/app/static/` | 웹 관리 화면 (HTML/CSS/JS, 빌드 불필요) |
| `server/sql/` | MySQL / SQLite 스키마 |
| `android/` | 수집 앱 (Kotlin, Android 8.0+) |
| `release/kakao-collector.apk` | 앱 설치 파일 |

## 1. 서버 설치 (Ubuntu 22.04 / 24.04)

서버에 SSH 로 접속해 아래 한 줄을 실행합니다. MySQL 계정은 **sudo 를 실행한 OS 계정과 같은 이름**으로 만들고, 비밀번호는 실행 중에 입력합니다(OS 계정과 같게 입력).

```bash
curl -fsSL https://raw.githubusercontent.com/rickyhan/mahalphp/claude/new-creation-dz2guv/deploy/install.sh | sudo bash
```

설치 과정에서 묻는 것: **MySQL 비밀번호**(2번), **Gemini API 키**(민원 분류용, 없으면 Enter 후 나중에 추가).
끝나면 다음이 출력됩니다.

```
 관리자 웹   : http://192.168.0.68:8000/admin
 관리자 계정 : admin / (무작위 생성)
 앱 서버 주소: http://192.168.0.68:8000
 앱 API 키   : (무작위 생성)
```

- 서비스 이름 `kakao-collector` — 재부팅 시 자동 시작. 로그 `journalctl -u kakao-collector -f`, 재시작 `sudo systemctl restart kakao-collector`
- 설정 파일 `/opt/kakao-collector/server/.env` (DB 계정·API 키·관리자 비밀번호·`GEMINI_API_KEY`, 권한 600)
- **업데이트**: 같은 설치 명령을 다시 실행 (설정·데이터 유지)
- 휴대폰이 서버와 **같은 Wi-Fi 가 아니면** 공유기에서 외부 포트 → `서버IP:8000` 포워딩 후 앱에 `http://공인IP:외부포트` 입력

## 1-1. 외부에서 접속하기 (nginx 경유)

사내망 nginx 서버(예: `192.168.0.26`)를 거쳐 외부에 공개합니다. 기존 nginx 사이트 설정은 건드리지 않고 설정 파일 하나만 추가합니다.

```bash
# ① nginx 서버(192.168.0.26)에서 — 전용 포트 28000 으로 받아 68번 웹 서버로 전달
curl -fsSL https://raw.githubusercontent.com/rickyhan/mahalphp/claude/new-creation-dz2guv/deploy/setup-nginx.sh | sudo bash

# ② 웹 서버(192.168.0.68)에서 — nginx 를 거쳐 온 실제 접속자 IP 를 인식 (한 번만, 이후 유지)
curl -fsSL https://raw.githubusercontent.com/rickyhan/mahalphp/claude/new-creation-dz2guv/deploy/install.sh | sudo env TRUSTED_PROXY=192.168.0.26 bash
```

③ 공유기 포트포워딩 추가: **외부 TCP 28000 → 192.168.0.26:28000**

④ 외부 접속 주소: `http://<공인IP>:28000/admin` (휴대폰 앱 서버 주소: `http://<공인IP>:28000`). 공인 IP 는 ① 실행 결과에 표시됩니다(`curl ifconfig.me` 로도 확인 가능).

- 포트·백엔드 변경: `sudo env LISTEN_PORT=28000 BACKEND=192.168.0.68:8000 bash setup-nginx.sh`
- 도메인이 있으면 `SERVER_NAME=kakao.도메인` 으로 실행해 80 포트 가상호스트로 만들고 `certbot --nginx` 로 HTTPS 적용을 권장합니다(외부 공개 시 로그인 비밀번호 보호).
- nginx 가 사진 업로드(최대 10MB)를 받도록 `client_max_body_size 20m`, 접속자 IP 위조 방지를 위해 `X-Forwarded-For` 를 nginx 가 덮어씁니다.

## 2. 앱 설치

1. 휴대폰 브라우저로 [APK 다운로드](https://github.com/rickyhan/mahalphp/raw/claude/new-creation-dz2guv/release/kakao-collector.apk) → 설치
2. **알림 접근 권한** 켜기 (Android 13+ 에서 스위치가 회색이면 앱 정보 → ⋮ → '제한된 설정 허용')
3. **배터리 최적화 예외** 설정
4. **서버 주소·API 키** 입력 → 저장 → 연결 테스트
5. (선택) **수집할 방 선택** — 모든 방 / 선택한 방만 / 선택한 방 제외

앱은 수집·전송만 합니다. 휴대폰에는 전송 대기분만 남고, 서버에 저장된 사진은 휴대폰에서 지웁니다. 맨 위 **🖥 웹 관리 화면 열기**로 웹을 엽니다.

### 카톡 챗봇 앱 (알림 유지) — `android/chatbot`

- 수집 앱과 같은 기능(카톡 알림에서 채팅방 이름·보낸 사람 수집 → 휴대폰 저장 → 30초마다 서버 전송, 카톡 답장으로 안내·업체 요청)을 하되 **알림을 하나도 지우지 않습니다** (카톡 알림 30개 정리·다른 앱 알림 지우기 없음).
- 앱 ID `com.mahal.kakaochatbot` 이라 기존 수집 앱과 함께 설치할 수 있습니다. Android 8.0 이상(갤럭시 S10+ · Android 12 포함).
- 공개 APK: `release/kakao-chatbot.apk` (서버 주소·키는 앱에서 입력). 기존 수집 앱 v2.3.6 은 `release/kakao-collector-2.3.6.apk` 로 보관.

| 검색 | 내용·보낸 사람 검색 → 해당 대화 위치로 이동 |
| 민원 | Gemini 가 민원으로 분류한 메시지를 **문제 단위로 묶어** 표시(같은 방·사람·분류로 설정 시간(기본 15분) 안 반복 = 1건, 시스템 설정에서 변경), 펼치면 관련 메시지 · 접수 안내 결과 · 지금 분류 / 실패 재시도 |

| 참여자 이력 | 입장·퇴장·내보냄·초대·대화명 변경·첫 발언 이력, 방별 참여자 |
| 아파트 관리 | 이름이 **별 하나(★ ☆ ⭐)로 시작하는 채팅방**을 아파트로 수집(별 두 개로 시작하면 제외), 아파트 이름(별 제외, 수정 가능) ↔ 원래 채팅방 이름(누르면 대화방 피드로 이동), **아파트별 담당 업체**(민원 분류마다 업체 지정·기본 업체 따름·보내지 않음), 메시지·민원 수, **다시 수집하기**(새 방만 추가, 고친 이름 유지) |
| 민원처리업체 관리 | 이름이 **꽉 찬 동그라미(● ⚫ 🔴 등)로 시작하는 채팅방**을 업체로 수집(**다시 수집하기**: 새 방만 추가, 같은 이름의 톡방 없는 업체에는 방 연결, 고친 이름 유지), 업체 이름 바로 수정 ↔ 원래 채팅방(누르면 대화방 피드로 이동), 담당 민원 카테고리 · 전화번호 · 사업자등록증 등 상세 수정, 업체 카톡방 전달 이력·다시 보내기 |
| 예약 메시지 | 정한 **날짜(한 번)·매일·매주(요일 여러 개)·매월(n일, 없으면 말일)** 시각에 선택한 채팅방으로 메시지 발송, `{날짜}` `{요일}` `{시각}` 치환, 미리보기·다음 발송 표시, 사용 켜기/끄기, 지금 보내기, 발송 이력 (서버 20초마다 확인, 30분 넘게 놓친 회차는 건너뜀, 휴대폰 전송은 1시간까지 대기) |
| 민원 카테고리 | 민원 분류 추가·이름 변경·설명(Gemini 판정 기준)·사용 여부·순서·삭제. '기타'는 고정 |
| 데이터 관리 | 방별 메시지·사진·민원 건수, **방별 삭제 · 선택한 방 삭제 · 전체 삭제**('전체 삭제' 입력 확인). 대화 화면에서는 **선택 삭제**(메시지 골라 지우기)와 **이 방 전체 삭제** |
| 시스템 설정 | 민원 자동 분류 사용 · 모델 · 같은 문제로 묶는 시간(분) · 접수 안내 사용·문구 · 업체 카톡방 처리 요청 사용·문구 · 워커 상태 |

- 아이콘은 Material Symbols(Apache-2.0) 일부를 `server/app/static/fonts/` 에 포함해 외부 요청 없이 표시합니다

### 민원 자동 분류와 접수 안내
- 대상: 공백 제외 5자 이상 텍스트 메시지(내가 보낸 메시지 제외). 서버 워커가 새 메시지마다 Gemini 로 20건씩 판정
- 분류: 웹 '민원 카테고리'에 등록된 분류 중 '사용' 중인 것 + 한 줄 요약 (기본값: 소음 · 누수·하자 · 주차 · 청소·쓰레기 · 시설·고장 · 관리비 · 보안·출입 · 생활·이웃 · 기타)
- 새 문제의 첫 민원(수신 30분 이내)이면 서버가 `[{분류}] 민원이 접수되었습니다.` 안내를 만들고, **휴대폰 앱이 그 방에 카톡 '답장'으로 전송** 후 결과를 보고합니다. (카톡 답장은 휴대폰 알림으로만 보낼 수 있어서 전송만 앱이 담당)
- Gemini 키는 서버 `.env` 의 `GEMINI_API_KEY` — 앱·저장소에는 없습니다. 메시지 내용이 Google 로 전송되며 사용료가 발생할 수 있습니다.

### 업체 카톡방 처리 요청
새 민원이 생기면 ① 민원이 올라온 방에 카톡 접수 안내를 보내고 ② 그 **민원 카테고리를 맡은 업체의 카톡방**에 처리 요청을 보냅니다(대화방 이름·민원 분류·요약·원문·보낸 사람·시각 포함). 같은 문제의 반복 민원·30분 지난 메시지에는 보내지 않습니다.

1. 업체를 카톡 대화방에 초대해 두고, 그 방 알림을 휴대폰 앱이 받게 합니다(한 번이라도 알림이 와야 웹에서 방을 고를 수 있음)
2. 웹 '민원처리업체'에서 업체마다 **담당 민원 카테고리**와 **처리 요청 보낼 카톡 대화방**을 지정
3. 문구·사용 여부는 '시스템 설정 > 업체 카톡방 처리 요청'. 항목: `{업체명}` `{방}` `{분류}` `{요약}` `{내용}` `{보낸사람}` `{시각}`
- 보내기는 휴대폰 앱이 카톡 '답장'으로 합니다. 그래서 **업체 톡방에서 최근에 알림이 와 있어야** 하며, 휴대폰·앱 재시작 직후에는 새 알림이 올 때까지 실패할 수 있습니다. 실패·만료 건은 '민원처리업체 > 업체 카톡방 전달 이력'에서 다시 보낼 수 있습니다.

### 참여자 이력의 조건
| 기록 | 조건 |
|---|---|
| 첫 발언·발언 수 | 항상 (실제 입장 시각이 아닌 첫 메시지 시각) |
| 입장·퇴장·내보냄·초대 | 카톡이 해당 안내 메시지를 **알림으로 보낼 때만** |
| 대화명 변경 | 카톡 알림에 사람별 **고유 키**가 있을 때만 (앱의 '알림 구조 진단' `person: key=` 로 확인) |

### 업체 문자 (뿌리오)

- 처리 요청 순서: **건물×업체 담당자 번호**(건물 관리 → 담당 업체 → '문자 담당자 지정') → 없으면 업체 연락처가 한 명뿐일 때 그 번호 → 번호가 없으면 업체 **카톡방**. 문자가 끝내 실패하면 카톡방으로 대신 보냅니다.
- **테스트 모드**(기본 켜짐): 모든 문자를 테스트 번호(기본 010-7572-8018)로만 보내고, 업체 카톡방 요청은 예전처럼 보냅니다. '시스템 설정 → 업체 문자'에서 끄면 실제 담당자에게 문자가 갑니다.
- 연동 정보: 서버 `.env` 의 `PPURIO_ACCOUNT`·`PPURIO_API_KEY`, 없으면 '시스템 설정 → 업체 문자'에서 입력. 뿌리오 연동신청관리에 서버 공인 IP 를 등록해야 합니다('연결 확인'에 IP 표시).
- 이력: '업체 발송 이력' 탭 — 문자 보냄 / 카톡으로 보냄 / 아직 못 나감 / 실패·만료 / 테스트 문자.

## 동작 원리와 한계
- **알림에 뜬 것만 수집**: 방 알림 꺼짐, 그 방을 보고 있는 중, PC 카톡 사용 중, '메시지 미리보기' 꺼짐이면 수집되지 않습니다.
- 사진은 알림의 **미리보기 이미지**만 저장됩니다(원본 아님). 미리보기가 없으면 "📷 사진" 기록만 남습니다.
- 단톡·오픈채팅 방 이름은 대화 제목 → 대화 바로가기(Android 12+) → subText → summaryText 순으로 찾습니다. 방 이름이 이상하면 앱의 **알림 구조 진단 → 이 내용 보내기** 로 원인을 확인합니다.
- 접수 안내는 앱이 실행 중일 때 받은 알림으로만 보낼 수 있어, 휴대폰 재시작 직후에는 실패할 수 있습니다(웹 민원 탭에 결과 표시).

## 보안
- 공개 저장소이므로 비밀번호·API 키는 저장소에 없습니다. 설치 시 입력받아 서버 `.env`(권한 600)에만 저장합니다.
- 웹: 서명된 HttpOnly·SameSite=Strict 세션, 5회 실패 시 10분 차단, CSP. 외부 공개 시 HTTPS 를 권장합니다.
- 단톡방 참여자의 대화·사진은 개인정보입니다. 보관 목적과 기간을 정하십시오. 삭제는 웹 '데이터 관리'에서 하며 되돌릴 수 없습니다(사진 파일도 함께 삭제).
